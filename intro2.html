Part 01

核心觀念：為什麼一般的 ChatGPT 做不好「譯後編輯 (PE)」？ Core Concept: Why Default ChatGPT Fails at Post-Editing

很多人在用 ChatGPT 改翻譯稿時，只會打一句：「請幫我把這段翻譯改得通順、道地一點。」 結果 AI 常常犯下三個讓專業譯者抓狂的毛病： When most people use ChatGPT to polish translations, they simply type: "Please make this translation smooth and natural." This vague instruction triggers three fatal flaws that drive professional translators crazy:

❌ 一般人的問法 / Naive Chat Prompt No Guardrails
"請幫我把這段翻譯改得通順、道地一點..."
"Please make this translation sound natural..."
1. 手太癢（過度編修 Over-editing）

原本機器翻譯（Raw MT）沒錯的句子，它也硬要換成同義詞或全部重寫，反而改出新錯誤。

Rewrites sentences that were already accurate in Raw MT, swapping synonyms unnecessarily and introducing fresh errors.

2. 不看原文亂腦補（幻覺 Hallucination）

只看中文字面順不順，卻把原文重要的限定詞漏掉了，或是自己亂加解釋。

Optimizes for target fluency while ignoring the source text—dropping crucial modifiers or inventing unstated facts.

3. 不守規矩（術語不一致 Term Drift）

客戶規定 Token 要翻成「詞元」，它偏偏一下翻「代幣」、一下翻「令牌」。

Client requires Token = "詞元", but AI randomly alternates between "代幣" (coin) and "令牌" (badge).

1. 最小修改原則（Minimal Edit Distance）

下達嚴格「負向限制」：沒錯的字不准動！只針對有問題的語法與誤譯動刀。

Strict negative constraints: If it isn't broken, don't touch it. Edit only verified accuracy or grammar defects.

2. 先體檢、再動刀（2-Stage GEMBA-MQM）

強迫 AI 先畫出「錯誤診斷表」抓出漏譯與誤譯，第二階段才准根據表格修改。

Forces AI to output an MQM error table first (spotting omissions/mistranslations), then fix only those flagged errors.

3. XML 密封保鮮盒鎖死術語（Zero-Cost Lock）

把強制術語表關進 <terminology_constraints> 標籤，100% 遵守且永久免費。

Seals glossary rules inside <terminology_constraints> tags for 100% compliance at zero cost.

基石二 / Pillar 2: Translation Technology Research Standards

學術界最新研究：什麼是「ISO 18587」、「GEMBA-MQM」與「三元組範例」？ Academic Standards in Plain English: ISO 18587, GEMBA-MQM & Few-Shot Triplets

1 ISO 18587:2017（國際譯後編輯標準）：決定你的「改稿力道」 / Choosing Your Editing Intensity
Light PE
輕度編修
「能看懂就好，只改致命錯字與誤譯，不改文筆」

"Good enough to understand. Fix only fatal mistranslations and grammar errors; do not polish style."

⚡ 適用：內部大量技術文件、即時客服、快速瀏覽
Full PE
完整編修
「改到像母語人士寫的出版級文章，徹底消滅翻譯腔」

"Publishable, native-level quality. Completely eliminate robotic 'translationese' and awkward phrasing."

✨ 適用：對外行銷文案、新聞稿、正式出版品、期末作品集
2 GEMBA-MQM 兩階段改稿法（微軟研究院提出）：「先列表抓蟲、再精準動刀」

研究發現，如果叫 AI 直接改稿，它會亂改；但如果規定它「第一階段：先列表格抓蟲並扣分 ➔ 第二階段：只針對抓出來的蟲進行修改」，AI 的準確度會暴增，而且不會亂改沒錯的句子！

Microsoft Research (Kocmi & Federmann) proved that asking AI to edit directly causes random rewrites. Forcing a 2-Stage Pipeline (Stage 1: Diagnose & Score Errors in an MQM Table ➔ Stage 2: Fix ONLY Flagged Errors) dramatically boosts accuracy and prevents over-editing.

3 Few-Shot Triplet（三元組示範教學）：與其講一百遍規則，不如給看一組「黃金對照」

與其跟 AI 講一百遍「請消除歐化中文」，不如直接給它看一組「三元組範例 (Triplet)」，AI 看完一組真實對照，馬上就能抓到你想要的改稿力道與文風！

Instead of lecturing AI on abstract style rules, show it one Few-Shot Triplet inside XML tags. One concrete before-and-after example calibrates GPT-5.6's editing intensity better than 500 words of rules.

① 原文 <source_text>

"The new API enables developers to deploy models with minimal latency."

② 爛機翻 <raw_mt> (歐化翻譯腔)

「新的 API 使開發人員能夠以最小的延遲進行模型的部署。」

③ 人類滿分範本 <gold_pe>

「透過新版 API，開發人員能以極低延遲部署模型。」

四大提示工程範本庫：哪一種適合你的任務？ The 4 Prompt Archetypes: Which One Fits Your Task?

點擊下方任一張範本卡片，即可直接將該模式載入下方的「步驟四：GPT-5.6 系統指令編譯器」中！ Click any archetype card below to inspect its plain-language logic and load it directly into the live compiler in Part 4.

範本 A / Archetype A ISO Light PE

🛡️ 守門員模式 (最小修改) The Gatekeeper (Minimal Edit)

核心技巧：下達嚴格的「負向限制（不准換同義詞、不准改文風）」，只修補嚴重誤譯與語法破洞。

Core Trick: Strict negative constraints (no synonym swapping or stylistic rewriting). Fixes only factual errors and broken grammar.

⏱️ 什麼時候用：趕時間、海量內部技術文件、只要看懂意思就好的場合。
範本 B / Archetype B Few-Shot Triplet

🎓 名師示範模式 (三元組) Master Demonstration (Triplet)

核心技巧：在指令裡塞入一組「原文 + 歐化機翻 ➔ 道地中文」的完美範例，讓 AI 模仿人類譯者的手藝。

Core Trick: Embeds a <source> + <raw_mt> ➔ <gold_pe> triplet so AI mimics human stylistic naturalness.

✨ 什麼時候用：行銷文案、新聞稿、演講稿等需要「徹底消滅機器翻譯腔 (Full PE)」的文章。
⭐ 最推薦教學與作品集 / Best for Portfolio
範本 C / Archetype C GEMBA-MQM CoT

🩺 先體檢再動刀 (MQM-APE) Diagnose First, Cut Second (CoT)

核心技巧：強迫 AI 先畫出「MQM 錯誤診斷表」並扣分（Critical -25 / Major -5 / Minor -1），最後才給出修改稿。

Core Trick: Forces an MQM error audit table with severity scoring before outputting the final post-edited translation.

🏆 什麼時候用：醫療、法律、技術手冊或翻譯品質評估 (LQA) 訓練，過程透明一目了然！
範本 D / Archetype D XML Glossary Lock

🔒 術語鐵衛模式 (XML 沙盒) Terminology Iron Guard (XML)

核心技巧：用 XML 標籤鎖死「強制翻譯詞」與「禁止翻譯詞 (DNT)」，並要求 AI 最後附上一張「術語合規檢查表」。

Core Trick: Locks mandatory terms and Do-Not-Translate (DNT) brands inside XML tags and requires a Term Compliance Audit table.

🔐 什麼時候用：軟體介面 (UI) 本地化、品牌專屬詞庫控管、API 技術手冊。
